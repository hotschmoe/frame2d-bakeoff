# Code review: zig-teak (run1p5, win-x64)

Scope: `stacks/zig-teak/` hand-written sources (src/*.zig, web/main.zig, js/bridge.js, build.zig, stack.sh), checked against SPEC.md. State reviewed: end of P2 (springs, releases, auto-restraint are in).

| Item | Score | Justification |
|------|------:|---------------|
| Structure | 4 | Clean layering: model.zig (types/JSON/gen), solver.zig (RCM + skyline), engine.zig (analysis), report.zig (results JSON), shared by cli.zig, server.zig (+store.zig, sweep.zig) and the UI (state.zig = Model/Msg/update, ui.zig view, canvas.zig, table.zig, bench.zig), with entry points platform.zig and web/main.zig. The weak spot is `engine.solve` (engine.zig:231-545), one 315-line function doing validation, springs, auto-restraint, numbering, assembly, factorisation and post-processing. |
| Naming and readability | 4 | The solver is easy to follow: doc comments cite SPEC sections, and the LDLᵀ and solve steps carry inline formulas (solver.zig:220-275). Elsewhere names are terse (`nn`, `nm`, `ef`, `st`, `pnode`, `restr`, `sh`, `tl`), and there is some leftover code: `_ = new_start` (solver.zig:49,59), a duplicate `comp`/`comp_names` (engine.zig:312,421), and an unused arena `ra` (cli.zig:109). |
| Error handling | 4 | Model errors are a typed `Outcome{ok,err}` (engine.zig:57), kept apart from Zig errors. The CLI exits 2 with the error JSON on stdout (cli.zig:83-87) and 1 otherwise (cli.zig:27-30). The server returns 422 (server.zig:116-118, 174-176), 400 for bad JSON and 500 for internal errors. The UI shows `code: detail` via `textDanger` (state.zig:169, ui.zig:115). Gaps: an empty member or node list crashes instead of returning an error (see defects), a bad request body closes the socket without a response, and JSON parse errors lose their location. |

The only `@ptrCast` outside those is the standard allocator vtable idiom (counting.zig). The engine has no raw pointers. Threading is explicit: the store has a mutex (store.zig:7), sweep uses atomics with one arena per variant (sweep.zig:18-36), and `Counting` is documented as single-threaded. Weak points: an unchecked null from `sqlite3_column_text` (store.zig:42), ignored `sqlite3_bind_text` return codes, the DB never closed, mutable globals (`state.clock`, `boot_bench`, `g_io = undefined`), and the sweep error arena being the request's non-thread-safe arena, made safe only by the `swap` guard (sweep.zig:53-55). |

## Load-type touch points

Adding, for example, a member point load or a trapezoidal load:

1. `src/model.zig:LoadCase`: new load struct and array field (model.zig:36-43).
2. `src/model.zig:write`: serialise it so UI Save round-trips (model.zig:218-242).
3. `src/engine.zig:solve`: reference validation, `invalid_ref` (engine.zig:351-356).
4. `src/engine.zig:solve`: per-case load accumulation and equivalent nodal loads into `rhs` (engine.zig:440-465; `udl_w` is a single scalar per member).
5. `src/engine.zig:fixedEnd` / `memberFixedEnd`: new fixed-end vector, condensed for mz releases (engine.zig:126-133, 189-192).
6. `src/engine.zig:solve`: end-force recovery `f = k·u + f_fixed` (engine.zig:486).
7. `src/engine.zig:solve`: station diagrams N/V/M, which today are UDL-only closed forms (engine.zig:498-503).
8. `src/engine.zig:solve`: equilibrium load resultant and moment (engine.zig:504-514).
9. Tests in `src/engine.zig`.

Unchanged: report.zig, server.zig, sweep.zig, state.zig, table.zig. canvas.zig:build does not draw loads at all today, so it needs no change.

## Notable

**Strengths**
- The engine is pure and allocator-parameterised, and every front end shares it. The CLI wraps it with a counting allocator to get the SPEC 5.2 alloc stats (cli.zig:80-92).
- Static condensation is implemented once (`condenseK` / `condenseF`, engine.zig:101-123). Both stiffness and fixed-end forces go through it, so released end moments come out exactly 0.
- RCM follows SPEC 4.4 step for step: component scan by lowest index, min-degree start, George–Liu loop, neighbours ordered by (degree, id) (solver.zig:103-181). The skyline factor and solve use SIMD `dot`, and the profile definition is the SPEC's.
- The pivot tolerance is on the `BENCH-EDIT:leaf` line (solver.zig:225). The `unstable` error reports the node id and component (engine.zig:419-425).
- The UI follows a clean Elm-style split (state.zig update vs ui.zig view), and its tests run headless through `teak.CmdBuffer`.

**Risks**
- `engine.solve` is a monolith, and its non-result allocations are freed by hand. Early `return fail(...)` paths leak `node_src`, `member_src`, `restr`, `supported` and the error detail unless the caller passes an arena; nothing documents that. `cli.zig:freeResults` (cli.zig:142-155) mirrors the `Results` layout by hand and will leak if a field is added.
- The server spawns one detached thread per connection with an 8 MB stack and no limit (server.zig:43-47). Each `/sweep` spawns another `cpu_count` threads (sweep.zig:86-96).
- The UI drag path re-solves synchronously in `update` (state.zig:308). `lag_max` is hard-coded to 0 (bench.zig:106) and no per-frame log of `solve_ms` / `lag_frames` is kept, only the aggregate BENCH line.

**Defects**
- **[High] Empty node or member list crashes.** engine.zig:242 `for (1..nn)` and engine.zig:251 `for (1..nm)` are reversed ranges when `nn` or `nm` is 0. Safe builds panic (start > end). The ReleaseFast server and CLI hit undefined behaviour: the length underflows and `node_src[k]` / `member_src[k]` are read out of bounds. A model with nodes but no members (for example one fully supported node, which should be `no_free_dofs`), or `{}`, can bring down the whole server process instead of returning 422.
- **[Medium] Moment equilibrium is not checked.** The residual uses only the force components: `load_sum[2]` is computed but dropped at engine.zig:531, so moment equilibrium is never verified (SPEC 4.5 asks for the sum of reactions plus loads to equal zero).
- **[Low] Dangling save buffer.** `save_bytes` (state.zig:261-264) is allocated in `model_arena`. `generate` resets that arena (state.zig:116) and `loadJson` frees it (state.zig:129), so an in-flight download effect can be left pointing at freed memory. Each Save also grows the arena without bound until the next load.
- **[Low] Unchecked SQLite results.** store.zig:42 `@ptrCast` of `sqlite3_column_text` is not null-checked; it can be null on SQLite OOM. That is undefined behaviour in ReleaseFast. The `sqlite3_bind_text` return codes are also ignored (store.zig:28-29, 40).
- **[Low] Bad body closes the socket with no reply.** server.zig:90 maps a read failure to `error.BadRequest`, and handleConn (server.zig:66) then closes the connection with no HTTP response. After a 413 that was decided from Content-Length (server.zig:88), the unread body stays on a keep-alive connection.
- **[Low] Sweep can return a silent zero drift.** It fills `roof_drift_W = 0` when there is no case `W` (sweep.zig:59-63). The top-left node is picked by raw coordinates in model order, not by id (sweep.zig:76-80). `model.clone` already copies `sections`, and runOne copies them again (sweep.zig:44-45).
- **[Low] `FRAME2D_ADDR` rejects bracketed IPv6.** The address is split on the last `:` without stripping brackets, so `[::1]:8080` fails to parse (server.zig:29-31).
- **[Low] Member table can show stale order.** Sorting is not re-applied after a re-solve, so during a drag the order no longer matches the new values (table.zig / state.zig:164 only resets the row count).
