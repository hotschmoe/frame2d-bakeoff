## Deviations

- **Concurrency (SPEC 2.10).** Up to 3 agents run at once to save time, so agent wall times and SPEC 8.1 build timings are **indicative only**. Overlaps are listed per row below.
- **No whole-run accounting (SPEC 9.7).** Windows has no per-run cgroups; `harness/measure.sh` uses its psutil fallback (`measure_fallback.py`), so Linux-only fields are null.
- **dvui smoke test occupies a slot.** The SPEC 15.6 smoke test runs as the start of the `zig` turn (queue position 2). While it runs, `rust` (position 3) takes the third slot. `zig` P1 starts only after the smoke test passes.
- **zig P1 prompt note.** The `zig` kickoff text says "Run the SPEC 15.6 smoke test first". Since the orchestrator already ran it, one orchestrator line was added after the verbatim kickoff, saying the smoke test passed and giving the pinned dvui commit, so the agent does not repeat it. No smoke-test code was handed over.
- **Harness `bash` on Windows (fixed mid-run, human-authorized 2026-10-23).** `conformance.py` (without `--bin`) and `measure_fallback.py` started plain `bash`; Windows resolves that to the System32 WSL stub (no distro), so `build_cli_release` failed and agents' `measure.sh` builds were not recorded. Agents worked around it (direct builds or `--bin`). The human authorized the orchestrator to patch both files to prefer `$F2D_BASH`, then Git for Windows bash, and to convert MSYS `/c/...` paths printed by `stack.sh`. Committed separately at 23:23. Consequence: SPEC 8.1 build-wait data from measure.sh is missing for builds before the fix (rust P1/P2, and early zig-flutter / zig P1). At 23:24 the orchestrator sent the running zig-flutter and zig P1 agents a one-line notice of the fix, asking them to route builds through measure.sh from then on; each is asked to log it as an intervention.
- **Goldens (rule 10): resolved 2026-10-23 23:30, human-authorized.** `rust` was first to pass P1. Its `gen 10 10` matches `fixtures/golden/reference/gen_10_10.results.json`: displacements to 1e-8 (0 diffs), profile exact (10221 / 7575, 330 free DOFs), residuals <= 3.4e-13 (50x50: <= 2.4e-11). But `diff_golden` reports 5 diffs: case D member 60 `end_forces[2]`, `end_forces[5]`, `stations[0,9,10].M` are roundoff-zero (rust 1.4e-10..1.8e-10 vs reference 2.9e-11..3.7e-11; abs floor 1e-10). The human authorized a tolerance change: `harness/conformance.py` golden abs floor is now max(1e-10, 1e-12 x the largest |value| of the same field in the golden file); rel 1e-8 and exact profile unchanged. This deviates from the SPEC 6.3 text (abs floor 1e-10), which was not edited. Then `fixtures/golden/gen_10_10.results.json` and `gen_50_50.results.json` were generated by the rust P2 binary (tag p2-done-rust; P2 does not change P1 models). Checks: rust vs reference golden 0 diffs and reference vs rust golden 0 diffs at the new tolerance; roof `ux` under W (node 111) rust 0.03934288721049803 vs reference 0.039342887210503594; residuals <= 3.4e-13 (10x10), <= 2.4e-11 (50x50); `conformance.py reference all` 22/22 and `rust all` 22/22.
- **Cross-agent process kill (rust-flutter P1 report).** Around 23:50-23:55 the rust-flutter agent killed `frame2d_app.exe` by image name (`taskkill /IM`, `Stop-Process`). Other Flutter stacks use the same exe name, so a zig-flutter P1 or go-flutter P1 bench run may have been killed. zig-flutter P1 still reported all bench modes before its 23:55 end; go-flutter P1 was still running and could rerun. Bench numbers from agents are indicative only regardless. From rust-flutter P2 (00:42) on, every agent prompt carries one extra orchestrator line: kill only processes you started, by PID, never by image name.
- **rust-flutter extra Rust target.** Added `x86_64-pc-windows-msvc` (the engine DLL must be x64 for the emulated x64 Flutter). Component added to the pinned toolchain, no upgrade.
- **go-zig-flutter P3 prompt notes.** After the verbatim P3 kickoff, one orchestrator paragraph states the fork origin (tag `p2-done-go-flutter`, baseline passing), to add a P3 section to the inherited `AGENT_LOG.md`, Zig 0.17.0, and the kill-by-PID rule. The P3 kickoff has no "Read CLAUDE.md/SPEC.md" or "date" lines of its own; the standard prefix and suffix supply them. Note: go-flutter already built its c-shared desktop library with `zig cc` (x64 target) before the fork.

- **go-zig-flutter P3 stall.** One agent tool call (backgrounding a desktop bench script) returned only after ~6.5 h (01:35 to 08:04 local; transcript timestamps), most likely machine sleep or a tool stall, not agent work. The agent estimates ~1.5 h of active work; the orchestrator did not count the gap against the 3 h time box. No intervention was sent.
- **Measurement campaign: reduced repetitions (human-approved 2026-10-24).** Fewer runs than SPEC 8/9 ask for, same on every machine: runtime benches 3 runs (SPEC 5); edit builds hyperfine 3 runs + 1 warmup (SPEC 10 + 1); cold builds 2 runs (SPEC 3); cache footprint 10 leaf+struct cycles (SPEC 50); hot reload / engine-edit-to-app 3 reps; oha unchanged at 30 s. Options: `runtime/run.sh <stack> --runs 3`, `buildloop/run.sh <stack> all --cold-runs 2 --runs 3 --warmup 1 --cycles 10 --engine-runs 3 --hot-reps 3 --zig-reps 3`. Medians are the headline; p95/p99 of builds are noisier than SPEC intends, and 10 cycles shows cache-growth trend but cannot prove it plateaus.
- **Measurement campaign: serial, one agent per stack.** Each campaign agent runs alone on the machine (no other agent work), with a keep-awake process preventing sleep. Harness fixes made during the campaign are logged in `CAMPAIGN_LOG.md`.
- **SPEC 8.1 classification: one fresh classifier for all stacks** (not one per stack as `harness/agentlog/README.md` suggests), for label consistency.
