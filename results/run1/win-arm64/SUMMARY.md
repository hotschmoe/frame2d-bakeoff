# Frame2D bake-off: run1 on win-arm64

Generated by `python harness/report.py run1 win-arm64`. Every number below is also in `summary.json`.

## Caveats (read first)

- **Emulation.** Flutter (Dart SDK, engine, the desktop app and its engine DLL) and the Playwright Chromium run **x64-emulated** on this ARM64 Windows laptop; the pure stacks (rust, zig, go) are native arm64. Flutter-vs-pure numbers are not a like-for-like language comparison here. Compare Flutter stacks with each other, and pure stacks with each other.
- **Reduced protocol (human-approved).** Runtime benches 3 runs (SPEC: 5); edit builds hyperfine 3 runs + 1 warmup (SPEC: 10 + 1); **cold builds 2 runs** (SPEC: 3, so the cold p50 is the mean of two); hot reload / engine edit 3 reps; oha 30 s as in SPEC. zig-flutter `cli`/`desktop` have 5 runs. Medians are the headline; SPEC p95/p99 of builds are not meaningful at n=3.
- **Trimmed scope.** Measured: binary size, code size, CLI/desktop/web/server runtime, cold builds, edit builds, no-op, hot reload (Flutter), engine-edit-to-app (Flutter). **Not measured:** cross-compile (8.7), under-the-hood (8.8), alternate web builds, cache footprint (9.4), build breakdown (9.5), tuned variants / Zig incremental (9.3), contention (9.6), whole-run accounting (9.7). Machine cost is Linux-only (SPEC 15.4) and is not scored. zig-flutter's extra hood/xcompile/web_alt data is ignored.
- **Agent runs overlapped** (up to 3 at once, SPEC 2.10 deviation), so agent wall times and build waits are indicative only. Agent cost is an assumed Sonnet-class list-price estimate (harness/agentlog README). One fresh classifier labelled the failures of all stacks.
- **Windows accounting.** Build `cpu_s` and peak memory come from psutil sampling (50 ms) and under-count short-lived children; server CPU-seconds have ~15.6 ms resolution.
- **Web.** Headless Chromium uses SwiftShader (software GL), same flags for all. Web build flavor differs by stack: rust = native wasm app, zig = native wasm app, go = native wasm app, rust-flutter = Flutter dart2js (CanvasKit), zig-flutter = Flutter dart2js (CanvasKit), go-flutter = Flutter --wasm (skwasm), go-zig-flutter = Flutter --wasm (skwasm).
- **go-zig-flutter** is a P3 variant of go-flutter (Zig engine, Go server). It has no P1/P2 agent run of its own, so it has no Agent-handling or P2 change-request scores (its P3 numbers are shown separately). Its first edits pass was invalid and was rerun; only the rerun is in the results.
- **Scores are indicative.** One run, one machine, small n, concurrent agents. Toolchain versions are frozen in `results/run1/versions.md`.

## How to read this

- **Flutter vs pure** is confounded by x64 emulation of Flutter and Chromium on this ARM64 machine (desktop startup, frame times, web numbers, Flutter build times). Compare Flutter stacks with each other; the engine-bound CLI and server numbers are the cleanest cross-stack comparison.
- **Web flavor differs** (see caveats): TTI and transferred bytes include the dart2js/CanvasKit vs `--wasm`/skwasm choice, not only the engine language.
- **Zig render p50 mostly measures draw-command building**; a very low render p50 does not mean the solve is fast. Look at drag p50 and the CLI numbers for the engine.
- **go-zig-flutter dev loop:** its `build_check`/`build_dev` redo every step regardless of input, so no-op ~ edit (CAMPAIGN_LOG). Its numbers are the real per-call cost, not a measure of incremental compilation.
- **Cold builds** use 2 runs (p50 = mean of two) and can include first-run cache effects. Treat differences under ~30% as noise.
- **Flutter desktop drag/render p50** is partly frame pacing (vsync-like 16-30 ms) and the emulated compositor; `solve_p50` inside is the engine part.
- **Server** runs through each stack's own `run_server`; for go and go-zig-flutter that builds a dev-profile binary (unstripped Go server, ReleaseSafe Zig lib). That is what is measured. Go servers show GB-scale peak RSS under 64 connections of a 50x50 solve.
- **Agent-handling** numbers come from concurrent runs; P2 times of 1-3 minutes are a handful of tool calls, so P2 deltas are small-n.
